# NRFI/YRFI matchup routing correction

## Finding

At base commit 3a25de8, computeNRFIPrediction resolved lineup-card offense against the opposing pitcher's throwing hand, but supplied that value only to Poisson. ZIP used overall team offense; Markov recomputed team handedness without the lineup card; MAPRE used team sOPS+ without the matchup adjustment. Their active weights total 88%. This muted a supplied lineup change and made the models evaluate different matchup contexts.

## Correction

Pass the resolved matchup factor to the half-inning ensemble. ZIP and Markov consume it directly. MAPRE retains its sOPS+ baseline and scales its base intensity by matchup offense / overall team offense, avoiding a second full offense multiplier. Poisson retains its already-adjusted lambda. Existing callers without an override preserve their former behavior. Nonfinite or nonpositive overrides fall back; duplicate top-three batting slots do not qualify as a complete lineup.

The home pitcher receives the away batting factor and vice versa. Tests check this routing, directional sensitivity, unchanged opposite-half output, neutral baseline preservation, and malformed-input fallback.

The homepage methodology now matches the base engine's active weights, anchor, clamps, and identity calibration. This does not change deployment flags or activate trained model artifacts.

## Validation limits and next gate

This is a correctness fix, not a measured increase in predictive accuracy. No game-level historical dataset or database credentials were available in this checkout. Aggregate artifact results cannot establish a paired before/after improvement for this patch.

Before claiming an accuracy lift:

1. Freeze the baseline commit and this candidate. Score identical games using only features available before first pitch, including the lineup publication time. Never substitute present-day team or pitcher splits for historical inputs.
2. Use chronological development, calibration, and untouched evaluation windows. Fit any ensemble weights, matchup tilt, or calibration only before the evaluation window. Group both halves and duplicate snapshots of a game together.
3. Compare paired game-level Brier score and log loss, accuracy, AUC, calibration, and coverage. Report a date-block bootstrap interval for candidate-minus-baseline loss. Include a training-only league-rate baseline.
4. Report posted-lineup and missing-lineup subsets separately, plus pitcher hand, season, and probability buckets. A routing correction can still worsen empirical loss if an upstream matchup estimate is poor.
5. Require lower held-out probability loss and acceptable calibration before describing the candidate as more accurate. Do not tune on this evaluation set after inspecting it; reserve a later window for subsequent changes.
6. If evaluating betting returns, use recorded pregame prices with timestamps; exclude missing prices instead of presenting synthetic -110 prices as executable odds.

The current 5% lineup tilt and base ensemble weights remain heuristic. This change does not validate them, retrain DeepNRFI, or establish profitability. Version any subsequent calibration against predictions generated by the corrected engine.
